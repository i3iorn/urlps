# urlps 0.7.0

Release date: 2026-08-10

A production-readiness release. It fixes a security bypass and two
data-correctness bugs, adds RFC 3986 reference resolution, and makes the
project's CI and packaging claims true. See [MIGRATION.md](../MIGRATION.md) for
upgrade steps.

## Highlights

- **Closed an SSRF bypass**: obfuscated IPv4 forms such as `0x7f000001` and
  `017700000001` addressed loopback but were accepted with SSRF protection on.
- **Stopped corrupting query strings**, including a case where one parameter
  became two — a parameter-smuggling vector.
- **Repaired three query mutators** that were silent no-ops.
- **Added `join()`** for RFC 3986 Section 5 reference resolution.
- **Made the `Typing :: Typed` claim true** — `py.typed` had never shipped.
- **Made CI gates real** — `mypy`, `bandit` and lint could not fail the build,
  ~48 property-based security tests silently skipped, and coverage was never
  measured.

## Security

### SSRF bypass via obfuscated IPv4 (most significant)

`parse_url()` accepted hosts that address internal services, with SSRF
protection enabled under the default policy:

| URL | Actually addresses | 0.6.1 |
|---|---|---|
| `http://0x7f000001/admin` | 127.0.0.1 | accepted |
| `http://017700000001/admin` | 127.0.0.1 | accepted |
| `http://0xc0a80101/admin` | 192.168.1.1 | accepted |

All three resolve to those addresses under the `inet_aton` semantics used by C
resolvers, libcurl and most HTTP clients.

The two obfuscation checks each covered only part of the space: the decimal
check required an all-digit string within 32 bits, so `017700000001` (which is
17,700,000,001 read as decimal) failed the range test and was never retried as
octal; the octal/hex check required exactly four dot-separated parts, so every
dotless form was skipped.

Now handled by a complete implementation of the classic grammar — `a`,
`a.b`, `a.b.c`, `a.b.c.d`, each part decimal, octal or hex — cross-checked
against `socket.inet_aton`, with no false positives introduced on public hosts.

### Checks now fail closed

A check that cannot reach a verdict no longer reports success:

- `_check_resolved_ips_safe` skipped addresses it could not parse, so a
  resolution returning only unparseable addresses reported "safe" without
  checking anything. An empty result also reported safe.
- `_verify_connection_safe` returned safe for an empty address list and for an
  unparseable peer. Genuine connect/timeout errors still honour the
  `dns_fail_open_on_connect_error` policy knob — that is a deliberate
  availability tradeoff; being unable to *determine* the peer is not.

### `check_phishing=True` no longer degrades silently

With an unreachable feed, every host was reported clean — the caller opted into
a protection and received none, with no exception and no signal. A
`PHISHING_DB_UNAVAILABLE` finding is now emitted.

This required giving severity meaning: `validate_url_security` raised on the
first finding regardless of severity. It now raises only on `critical`/`major`
and returns advisory findings without rejecting the URL, so a degraded optional
check does not become a hard parse failure.

### DNS resolution is bounded

`socket.getaddrinfo` takes no timeout and is bounded only by the OS resolver
(5–30s under packet loss). The documented `timeout_seconds` applied only to the
subsequent connect. Resolution now runs in a worker thread and is abandoned on
timeout.

### Thread safety

`DNSRateLimiter` now holds a lock across its whole check-and-consume cycle;
previously the budget test and the decrement were separate steps, so concurrent
callers could each pass and overspend it. Cleanup could also raise
`RuntimeError` by iterating the per-host map while another thread inserted into
it. Both lazy global initialisers use double-checked locking, which
additionally stops every thread arriving on a cold phishing cache from starting
its own multi-megabyte download.

Reported honestly: this is correctness and free-threaded (PEP 703) hardening.
The token-bucket race could not be made to reproduce under the GIL across 200
trials of 64 barrier-synchronised threads.

## Fixed

### Query strings are no longer rewritten on parse

Parsing returned a re-serialization of the decoded pairs rather than the input.
Because `QUERY_SAFE` listed `&`, `=` and `+` as safe, `quote_plus` refused to
escape them:

| Input | 0.6.1 output | Problem |
|---|---|---|
| `?a=hello%20world` | `?a=hello+world` | lossy |
| `?sig=aGVsbG8%3D&x=1` | `?sig=aGVsbG8=&x=1` | breaks signature verification |
| `?q=C%2B%2B` | `?q=C++` | the `+` now decodes as a space |
| `?q=a+%26+b` | `?q=a+&+b` | **one parameter becomes two** |

The last is a parameter-smuggling vector — it re-parses as two parameters, so
anything echoing `str(url)` onward forwards an attacker-injected parameter.
`str()` was also not idempotent.

### Query mutators were silent no-ops

`with_query()`, `with_query_param()` and `without_query_param()` returned an
unchanged URL. Each computed a correct new query, then `copy()` passed
`compose()` a dict still carrying the old `query_pairs`, which took precedence.

### Other

- `copy()` never initialised `_audit_manager` despite it being in `__slots__` —
  a latent `AttributeError` and no audit events for any `with_*` chain.
- `parse_relative_reference()` rejected any reference containing `://`
  anywhere, so `/redirect?next=http://example.com` raised. This is the same
  substring-matching bug fixed in the scheme parser for 0.6.1, never applied
  here.
- `copy()`/`with_*` only type-checked overrides, so `with_host("not a valid
  host!")` produced a `URL` that `parse_url` would have rejected.

## Added

- **`join(base, reference)`** — RFC 3986 Section 5 reference resolution
  (`remove_dot_segments`, `merge`, the component-inheritance table). The
  security-preserving equivalent of `urllib.parse.urljoin`: the resolved target
  is validated, so resolution cannot bypass the library's checks. Previously
  there was none, so users fell back to `urljoin` — the one moment where an
  attacker controls part of the input. Validated against the RFC's own Section
  5.4 example tables and cross-checked against `urllib`.
- **`audit=AuditConfig(...)`** on `parse_url`, `parse_url_unsafe`, `join` and
  `build_secure`. The audit types were exported but unreachable; the README
  documented `set_audit_callback` and `set_audit_event_callback`, neither of
  which ever existed.
- **Public exports**: `DNSRateLimiter`, `DNSRateLimiterConfig`,
  `SecurityFinding`, `ErrorCode`, `PolicyInput` and the specific exception
  types. The README previously instructed importing the rate limiter from the
  private `urlps._security.dns_guard`.
- **`py.typed`** — the package advertised `Typing :: Typed` but shipped no
  marker, and `.gitignore` actively prevented adding one, so downstream type
  checkers ignored its annotations entirely.
- `check_against_phishing_db_detailed()` returning
  `(is_phishing, database_available)`.
- `docs/design/heuristics.md` documenting what `has_query_injection` and
  `has_suspicious_punycode` aim for and why they fall short.

## Changed / Breaking

- `str(url)` returns the query as supplied rather than re-encoded. Use
  `canonicalize()` for the old normalisation.
- **`strict=` removed** from `parse_url_unsafe()` and `URL()`. It duplicated
  `policy` and was silently ignored whenever a policy was also supplied. Use
  `policy="strict"`.
- `Builder.compose` gives an explicit `query` precedence over `query_pairs`
  (previously reversed).
- `Builder.QUERY_SAFE` no longer treats `&`, `=` and `+` as safe.
- `parse_url`'s docstring claimed eight "Always Enabled" features; the default
  `balanced` policy disables four of them. Corrected.

## Infrastructure

- CI gates are now blocking: `ruff`, `mypy` and `bandit` were `|| true` and
  could never fail the build. Fixing this required clearing 11 mypy errors.
- `hypothesis` is a required dev dependency; CI fails if the ~48 property-based
  security tests report as skipped.
- Coverage measured and gated at 90% (currently 95%).
- Python 3.13 and a Windows runner added; concurrency cancellation, explicit
  permissions, `setup-python` v5, dist artifact upload.
- `publish.yml` no longer publishes without running the test suite, and a
  manual `pypi` dispatch no longer also uploads to Test PyPI.
- Added `CONTRIBUTING.md`, `MIGRATION.md`, pre-commit config, dependabot, and
  issue/PR templates. Corrected `SECURITY.md`, whose supported-versions table
  still recommended 0.4.x.

## Test suite

1207 tests, up from 974. New: query round-trip and idempotency (including
property-based), RFC 3986 Section 5.4 conformance, public API and audit wiring,
SSRF bypass regressions, fail-closed behaviour, and the project's first
concurrency tests.
