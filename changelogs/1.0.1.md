# urlps 1.0.1

Release date: 2026-08-20

## Highlights

Pure internal cleanup following 1.0.0: the public API and every documented
behavior are unchanged. This release is a structural refactor plus a test
coverage push.

## Changed

- Decomposed `url.py` and `__init__.py`, which had accumulated most of the
  package's logic across the 1.0 security-hardening work, into focused
  private modules:
  - `_comparison.py` — equality, ordering, and hashing (`__eq__`, `__lt__`,
    `__hash__`, `is_semantically_equal`).
  - `_serialization.py` — `as_string()`, `canonicalize()`, and related
    string-producing logic.
  - `_entrypoints.py` — the public facade functions (`parse_url`,
    `parse_url_local`/`parse_url_unsafe`, `build`, `join`) that
    `__init__.py` re-exports.
  - A few smaller helper modules for validation and mutation logic that
    previously lived inline in `url.py`.

  The public surface (`urlps.parse_url`, `urlps.URL`, etc.) and every
  method's behavior are identical before and after — this is purely about
  making the codebase easier to navigate as it grows.

## Added

- Targeted edge-case and hot-path tests raising overall coverage to 96%+,
  closing gaps the 1.0.0 security work had left in `_validation.py`,
  `_security/policy.py`, and a few parser branches.

## Fixed

- Removed a small piece of dead code in `_validation.py`: duplicate
  `idna`-presence detection variables (`_idna_module`, `_HAS_IDNA`) that
  shadowed the single IDNA/UTS-46 entry point in
  `_security/_unicode/uts46.py` and were never actually read. No behavior
  change — `uts46.py`'s own `UTS46_AVAILABLE` flag was always the one
  everything else consulted.

## Security Notes

None. No security-relevant code changed in this release.

## Migration Notes

None. This release contains no API or behavior changes.
