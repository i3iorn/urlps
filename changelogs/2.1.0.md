# urlps 2.1.0

Release date: 2026-11-03

## Highlights

A maintenance release addressing six retroactive fixes from the v2.1.0 cycle:
new injection-payload detection opt-in (`flag_injection_payloads`), public
export of `redact_url_for_logs`, README documentation updates, improved
`resolve_security_policy` diagnostics, and a comment noting a mask-token
inconsistency.

## Fixed

- **Injection detection opt-in (#78).** `SecurityPolicy` now carries
  `flag_injection_payloads` (default `False` in all presets). When enabled,
  decoded path and query components are scanned for script tags and inline
  event handlers; matches emit warning-severity `SecurityFinding` entries.
- **Public API export (#74).** `redact_url_for_logs` is now exported from
  `urlps` and covered by a template-URL redaction test.
- **README documentation (#77, #76, #75).** Added sections on default
  schemes / HTTP-only override, deriving a modified policy with a DNS
  fail-open recipe, and validating URLs before template expansion (with
  `redact_url_for_logs` example). Improved `resolve_security_policy` error
  message for dict inputs.
- **Comment / consistency (#73).** Added comment noting mask-token
  inconsistency; no behavioral change.

## Security Notes

`flag_injection_payloads` is opt-in and off by default so existing callers
are unaffected. It operates on decoded component values, not raw strings,
to avoid false positives from encoded representations.
