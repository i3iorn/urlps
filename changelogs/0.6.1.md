# urlps 0.6.1

Release date: 2026-08-09

## Highlights

- Fixed a correctness bug where relative URLs with `://` embedded later in the string (the shape of almost every redirect/callback query parameter, e.g. `?next=http://host`) were incorrectly rejected as invalid.
- Fixed a reliability bug where an unreachable phishing-domain feed turned every `check_phishing=True` parse into a blocking network call.
- ~20% faster parsing on a representative mixed-URL benchmark, with no behavior change.
- Added `dns_rate_limiter` dependency injection across the public API for per-application/tenant DNS rate limiting.
- Repaired the CI pipeline, which had silently stopped running and silently stopped scanning since the src-layout migration and repository rename.

## Added

- `dns_rate_limiter` parameter on `parse_url()`, `parse_url_unsafe()`, and `build_secure()` for injecting a dedicated `DNSRateLimiter` instance (recommended for multi-tenant or concurrent applications; see README).
- `python-3.10` added to the CI test matrix, matching the package's declared minimum supported version.

## Fixed

- **Scheme parsing**: `parse_url()`/`parse_url_unsafe()` used a substring search (`"://" in url`) to detect a scheme, so any relative reference containing `://` later in the string -- most commonly a redirect target in a query parameter -- was misparsed as an invalid absolute scheme and rejected with a confusing error. Scheme detection is now anchored to the leading colon.
- **Security scanner**: the same substring-matching flaw in `extract_host_and_path()`, `has_parser_confusion()`, `is_non_canonical_url()`, and `get_canonical_url()` could mistake a query value for the URL's actual authority/host. Fixed via a shared, correctly-anchored helper used consistently across all four.
- **Phishing database reliability**: `check_phishing=True` re-attempted a network download on every call whenever the previous refresh had failed, since the failure timestamp was already being tracked but never consulted. A 5-minute cooldown now applies before a lazy check retries; explicit `refresh_phishing_db()` calls are unaffected.
- **CI pipeline**: `on.push`/`on.pull_request` still targeted a `main` branch that has never existed on this repository (the default branch is `master`), so CI never ran on pull requests or pushes to it -- only tag pushes ever triggered a run. Fixed the branch reference, and while doing so found and fixed three more silent failures the workflow had been swallowing with `|| true`: `mypy`/`bandit` were pointed at a `urlps/` directory that hasn't existed since the src-layout migration (bandit was reporting 0 lines scanned), and `pip-audit --progress spinner` used an invalid flag/value and errored on every run.
- **Bandit suppression scoping**: an existing `# nosec B104` comment on `constants.py` was attached to the wrong physical line and so was never actually suppressing the finding it was meant to; corrected the placement and added two more targeted suppressions for known-safe findings surfaced once bandit started scanning for real.
- Corrected `pyproject.toml` `project.urls` (pointed at the wrong GitHub owner and a `main` branch that doesn't exist here).

## Performance

- Cached `has_parser_confusion()`/`find_authority_marker()`, which were being recomputed 2-4x per parse on the identical URL string.
- Replaced `any(genexpr)`-based delimiter/ASCII checks with direct chained comparisons and `str.isascii()` on hot paths (3.5-12x faster per call in isolation).
- Removed a per-call closure allocation in query serialization.
- Net effect on a clean, non-profiler benchmark of 3000 mixed URLs: ~31.3us/parse -> ~25.1us/parse.

## Security Notes

- No new protections were added or relaxed in this release. The scheme-parsing fix corrects a false positive (legitimate relative URLs were being rejected); SSRF, path-traversal, homograph, and parser-confusion protections are unchanged in scope.
- Bandit static-analysis scanning in CI is now actually functional; it previously silently scanned zero lines of code on every run since the src-layout migration.

## Migration Notes

- None. This release contains no breaking API changes.
