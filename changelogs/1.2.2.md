# urlps 1.2.2

Release date: 2026-10-02

## Highlights

A security-hardening release from a dependency-consumer perspective: it makes
unencodable input fail fast with urlps exception types, restores the
`create_guarded_connection()` drop-in exception contract, closes DNS
rate-limit bypasses via host spelling variants, bounds the phishing feed
download, and makes cache-related environment variables warn and clamp
instead of silently honoring oversized values.

## Fixed

- **Surrogate rejection.** Lone surrogates (U+D800–U+DFFF) are rejected at
  parse time, and `build()`/`compose_url()`/`with_query_param()` raise
  `URLBuildError` for surrogate components. Previously such URLs parsed fine
  and crashed callers' `str()`/logging paths with a raw
  `UnicodeEncodeError` — outside the library's exception hierarchy.
- **DNS exception contract.** `DNSResolutionError` is now both an
  `InvalidURLError` and an `OSError`, so resolution failures raised by
  `create_guarded_connection()` are caught by socket-error-family retry logic
  (urllib3, `requests`, `except OSError` handlers). UnicodeError from IDNA
  inside `getaddrinfo` is mapped to the same error instead of escaping raw.
- **DNS key normalization.** Trailing FQDN dots are stripped from DNS
  cache/rate-limiter keys, so `example.com.`-style spellings can no longer
  bypass per-host rate limits or skip negative caching.
- **Phishing feed bounds.** The feed download is now chunked and bounded by a
  30-second wall-clock deadline; a trickle-feeding or wedged feed can no
  longer hold the refresh lock (and every queued `check_phishing=True` parse)
  indefinitely. An unencrypted `http://` feed URL is accepted but warns at
  import.
- **Env-var hardening.** `URLPS_CACHE_SIZE_*` and `URLPS_CACHE_MAX_KEY_LENGTH`
  values are validated with a warning, and oversized entries are clamped to
  ceilings instead of being honored verbatim — restoring the documented
  anti-memory-pinning guarantees.
