# urlps 0.7.1

Release date: 2026-08-18

## Highlights

Robustness and maintainability follow-ups identified right after 0.7.0
shipped. No public API changes, no behavior changes — this release is
entirely new regression coverage, one documented (not code) tradeoff
decision, and developer-facing tooling/docs.

## Added

- **Standing guard against the fail-open pattern reappearing** in
  `_security/`: a static test scans every security predicate for
  except-blocks that return a bare `True`/`False`/`None` literal and fails
  unless it's on a hand-reviewed, justified allowlist, so a new fail-open
  return (the class of bug the 0.7.0 SSRF fix corrected) needs either a fix
  or an explicit, reviewed exception rather than slipping in silently.
- **Property-based testing extended** beyond query round-tripping to the
  other two places doing non-trivial parsing logic:
  - `remove_dot_segments`/`merge_paths` (`_resolve.py`): no output path
    segment is ever a literal `.`/`..`, the transform is idempotent, and it
    never lengthens the path.
  - `_parse_inet_aton_ipv4` (`ip_utils.py`): generalizes the existing
    fixed-list cross-check against `socket.inet_aton` to arbitrary 1-4 part
    hosts with independently decimal/octal/hex parts, plus a round-trip
    check through `ipaddress.IPv4Address`.
- **A real use for the `slow` pytest marker**: a sustained-load soak test
  checks the `DNSRateLimiter` token bucket's cumulative capacity across many
  refill/cleanup cycles, catching drift a single short burst can't.
- `Makefile` with a `check` target mirroring the CI `test`/`quality` jobs, so
  contributors have one documented command instead of four separate ones.
- `docs/architecture.md`: a module-layering map built from the actual import
  graph, documenting the parser/security separation and where "relative URL"
  logic lives across `_relative.py`/`_resolve.py`/`url.py`.
- `tests/test_readme_examples.py`: every fenced Python block in the README
  now executes in CI. This is a permanent guard for the exact bug class that
  slipped through 0.7.0 review (`set_audit_callback()`/
  `set_audit_event_callback()` were documented but never existed).

## Fixed

- `with_scheme(None)` regressed into rejecting `None` when every sibling
  `with_*` method (`with_host`, `with_query`, `with_fragment`, ...) still
  accepts it to clear the component. Restored consistent behavior.
- Cleared the accumulated `ruff` `UP` (pyupgrade) and `ruff format` debt
  (296 and 67 pending violations respectively) and enabled both permanently
  in CI and pre-commit, so the gap can't silently reopen.
- Wired up or removed 8 exception subclasses that existed in the public
  hierarchy but could never actually be raised: `RelativeReferenceError`
  and the `DNSRateLimitError`/`DNSResolutionError`/`DNSConnectionError`
  trio are now raised where a generic `InvalidURLError` used to be;
  `QuerySerializationError`, `PathNormalizationError`, `NetlocBuildingError`,
  and `MissingPortError` were removed since no natural call site exists for
  any of them. A consumer catching one of the kept types will now actually
  see it fire.

## Performance

- No changes. Profiled the per-call `ThreadPoolExecutor` in
  `_resolve_addr_info` (the DNS timeout path) as a candidate for a shared
  pool: reusing one saves ~220us/call, but a shared bounded pool
  permanently loses a worker to any resolution that hangs forever rather
  than erroring or timing out — a real risk for a library that has to
  assume adversarial DNS. Kept the self-healing per-call executor;
  documented the tradeoff inline so it doesn't need re-deriving.

## Security Notes

- No new protections were added or relaxed in this release. The fail-open
  guard test is a regression backstop for the class of bug fixed in 0.7.0
  (obfuscated-IPv4 SSRF bypass), not a new check.

## Migration Notes

- None. This release contains no breaking API changes.
